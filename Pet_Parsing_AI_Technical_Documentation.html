AUTO.RIA Analyzer

Техническая документация проекта Pet_Parsing_AI: назначение модулей, слои архитектуры, взаимодействие desktop-клиента с FastAPI, интеграции с AUTO.RIA и OpenAI, хранение данных и варианты развёртывания.

Python 3.14PySide6 Desktop FastAPIPostgreSQL 17 Docker ComposeOpenAI API

1. Назначение проекта

Pet_Parsing_AI — desktop-приложение для поиска автомобилей на AUTO.RIA, получения подробностей объявлений, сохранения результатов и формирования AI-анализа рынка.

Поиск ДВС / гибридов

Форма поиска автомобилей с двигателями внутреннего сгорания и гибридных автомобилей. Используются марка, модель, год, пробег, топливо, объём двигателя, коробка передач и привод.

Поиск электромобилей

Отдельная форма поиска электрических автомобилей. Справочники марок, моделей и типов топлива загружаются через backend.

Сбор данных и история

Backend получает идентификаторы объявлений, загружает карточки автомобилей, преобразует ответы API и сохраняет историю поиска в PostgreSQL.

AI-анализ рынка

Собранные объявления упаковываются в JSON и передаются в OpenAI API. Текст анализа сохраняется вместе с записью поиска.

3. Как проходит один поиск

  1. Пользователь выбирает параметры на странице ДВС/гибридов или электромобилей.
  2. Страница получает справочники через BackendClient. Длительные операции загрузки справочников выполняются в потоках QThread.
  3. При запуске поиска MainWindow создаёт SearchWorker. Он выполняет HTTP-запрос в фоновом потоке, чтобы интерфейс не зависал.
  4. BackendClient отправляет POST /searches/ с JSON и заголовком Authorization: Bearer ....
  5. FastAPI проверяет токен, валидирует данные через SearchRequest и передаёт запрос в SearchService.
  6. SearchService создаёт запись поиска через SearchRepository, формирует фильтры и вызывает интеграцию AUTO.RIA.
  7. ria_client.py запрашивает список ID объявлений и подробности каждого автомобиля. car_parser.py преобразует ответы API в dataclass-объекты автомобилей.
  8. Сервис формирует JSON с рыночными данными, сохраняет его в папку search/ и записывает найденные автомобили в PostgreSQL.
  9. market_analyzer.py формирует инструкции и входной текст, а openai_client.py отправляет запрос в OpenAI API.
  10. Текст AI-анализа сохраняется в файл TXT и в запись поиска. Backend возвращает результат клиенту.
  11. ResultsPage отображает найденные автомобили и анализ. HistoryPage получает список предыдущих поисков и их подробности через API.
Тайм-аут клиентского запроса на поиск установлен в (5, 600) секунд. При удалённом размещении reverse proxy должен поддерживать достаточно длинное ожидание ответа.

FastAPI-приложение создаётся в backend/main.py. Все маршруты приложения защищены общей зависимостью verify_api_token, поэтому клиент должен отправлять Bearer-токен.

8. База данных и хранение результатов

PostgreSQL

Docker Compose использует образ postgres:17-alpine. Данные PostgreSQL сохраняются в именованном Docker volume postgres_data.

ТаблицаМодельСодержимое
searchesSearchID, дата создания, статус, JSON-параметры поиска, текст AI-анализа и название модели.
search_carsSearchCarОбъявления, найденные в рамках поиска: ID AUTO.RIA, марка, модель, год, пробег, цены, тип топлива, URL, фото и raw JSON.

Между таблицами связь один-ко-многим: один поиск может содержать несколько найденных автомобилей. В SearchCar задано ограничение уникальности пары search_id + car_id.

Файловые результаты

Кроме PostgreSQL, сервис сохраняет JSON с данными рынка и TXT с AI-анализом в каталог search/ относительно корня backend-проекта. В текущем Compose для этой папки не настроен отдельный volume: файлы внутри контейнера могут исчезнуть при пересоздании контейнера. Для долговременного хранения нужно добавить bind mount, например ./search:/app/search, в секцию volumes сервиса backend.

Инициализация схемы

В архиве нет Alembic и нет автоматического создания таблиц при старте. Для чистой БД один раз запускается Base.metadata.create_all() с импортом backend.models. Для дальнейших изменений схемы рекомендуется внедрить миграции.
docker compose exec backend python -c "import backend.models; from backend.database import Base, engine; Base.metadata.create_all(bind=engine)"

11. Модель развёртывания

Локальная разработка

Windows-компьютер запускает Docker Compose (PostgreSQL + FastAPI) и desktop UI. Клиент обращается к http://127.0.0.1:8000.

Подходит для разработки

Удалённый backend

VPS запускает PostgreSQL и FastAPI. Windows-клиент обращается к домену API по HTTPS через reverse proxy.

Подходит для удалённого доступа

Что именно размещать на VPS

  • Репозиторий проекта или его серверную копию, необходимую текущему Docker build context.
  • Серверный .env, созданный на сервере.
  • Docker-контейнер FastAPI и PostgreSQL.
  • Постоянный volume PostgreSQL.
  • Reverse proxy и TLS-сертификат — настраиваются отдельно.

Что остаётся у пользователя

  • Исходный GUI или папка dist/Pet_Parsing_AI/.
  • Клиентский .env с BACKEND_BASE_URL и BACKEND_API_TOKEN.
Не путать: EXE — это desktop-клиент. Он не заменяет backend и не содержит PostgreSQL-сервер. Для работы поиска удалённый backend должен быть доступен по HTTPS.

12. Безопасность

  • API-ключ AUTO.RIA и ключ OpenAI должны находиться на backend, а не в публичном репозитории.
  • PostgreSQL не должен быть доступен напрямую из интернета. В текущем Compose порт базы не публикуется наружу.
  • Внешний доступ к FastAPI рекомендуется организовать через HTTPS reverse proxy.
  • Секреты хранятся в `.env`, который исключён из Git и Docker build context.
  • Текущая авторизация использует один общий Bearer-токен. Он не является пользовательской системой аутентификации.
  • Сборщик EXE копирует весь исходный `.env`. Если в нём есть серверные секреты, они попадут в дистрибутив.
